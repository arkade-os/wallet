# Running the RFQ Lightning send e2e

`src/test/e2e/lnsend.test.ts` drives the wallet's `arkade:BTC -> lightning:BTC`
send against a real solver on a local regtest stack: real quote over Nostr,
real covenant, real Ark funding transaction, real Lightning payment, real
claim. It skips itself when the solver card is missing, so a plain `pnpm
test:e2e` on a machine without a solver stays green rather than failing as
though the wallet were broken.

Three things have to be true. The first is already wired into `.env.regtest`;
the other two involve a second repository, so they are manual.

## 1. arkd's exit delay (already configured)

`.env.regtest` raises every arkd delay above 512 seconds. This is not a
preference: 512 is the BIP68 unit for relative timelocks AND the boundary
where arkd switches a delay's meaning from a block count to seconds. The
stack's default of 5 is below one unit, and both sides of a swap refuse it
outright rather than round it — the wallet's client throws `server exit delay
must be at least 512s of seconds`, the solver's `5 is below 512s and is a
block count, not seconds`. Lightning send cannot run on regtest without it.

arkd also refuses a config that mixes the two unit regimes, so the whole set
crosses over together. It reads them only when its database is created, so
changing them means `pnpm regtest:clean` — a plain restart keeps the old
values and, worse, can leave the stack half-configured.

## 2. The swap service, in outbound Nostr relay mode

From a checkout of `arkade-os/lightning-swap-service` with the Nostr transport
(branch `claude/arch-excalidraw-rfq-review-2rijb1` at time of writing; `main`
still carries only the dev broker framing):

```bash
pnpm install && pnpm build

cat > .env.regtest <<'EOF'
SWAP_NETWORK=regtest
LN_BACKEND=lnd
LND_SOCKET=localhost:10010
LND_CERT_PATH=./boltz-lnd-tls.cert
LND_MACAROON_PATH=./boltz-lnd-admin.macaroon
ARK_MNEMONIC="<any bip39 phrase>"
ARK_SERVER_URL=http://localhost:7070
EMULATOR_URL=http://localhost:7073
RELAY_URL=ws://localhost:10547
RELAY_PROTOCOL=nostr
ARK_DB_PATH=.data/ark-regtest.sqlite
SWAP_DB_PATH=.data/swaps-regtest.sqlite
EOF

# boltz-lnd is the stack's own node: already funded and channeled to the
# second `lnd` node by arkade-regtest's setup, so the payment the test asserts
# crosses a real channel.
docker cp boltz-lnd:/root/.lnd/tls.cert ./boltz-lnd-tls.cert
docker cp boltz-lnd:/root/.lnd/data/chain/bitcoin/regtest/admin.macaroon ./boltz-lnd-admin.macaroon

# Fund the provider. "No inputs found" here means the indexer is a block
# behind the faucet — just run it again.
node --experimental-eventsource --env-file=.env.regtest \
  scripts/regtest-fund.mjs <path-to>/wallet/regtest 0.01

node --experimental-eventsource --env-file=.env.regtest dist/cli.js relay
```

It should log `relay ingress open (outbound only, nostr) ... as <pubkey>`.
`node scripts/probe-relay.mjs ws://localhost:10547 <pubkey>` answers whether
the path is live, and which side is at fault when it is not.

## 3. The solver card

The card is what makes the corridor exist — it carries the solver's pubkey and
its relays, and there is no URL to configure instead. It is generated rather
than committed because its `discovery_pubkey` is that deployment's own key.

```bash
RELAY_URL= SOLVER_CARD_RELAYS=ws://localhost:10547 \
  node --experimental-eventsource --env-file=.env.regtest dist/cli.js card regtest-lightning \
  > <path-to>/wallet/.regtest-lightning.card.json
```

`RELAY_URL` is cleared for this one command on purpose. A card's relays MUST
be `wss://` — the registry schema says so and `@arkade-os/solver-discovery`
rejects the whole card otherwise — while the service itself dials nak over
plain `ws://`, which nothing validates. Both ends meet on the same relay;
only the wallet goes through the TLS proxy (`relay-tls.nginx.conf`, brought up
by `pnpm regtest:start`, cert generated by `scripts/gen-relay-tls-cert.mjs`).
Playwright's `ignoreHTTPSErrors` is what makes the browser accept that cert,
so it never has to be trusted anywhere.

Set `LN_SOLVER_CARD_PATH` if you keep the card somewhere else.

## Running it

```bash
pnpm test:e2e -- src/test/e2e/lnsend.test.ts
```

A full run takes ~20s: most of it is wallet setup, with quote-to-claim landing
in about 2.5 seconds.
